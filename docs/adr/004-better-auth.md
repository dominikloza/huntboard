# 004: Better Auth with GitHub sign-in and guest accounts

- **Status:** Accepted
- **Date:** 2026-11-07

## Context

Recruiters will not create an account to look at a portfolio app, so a one-click demo is a hard
requirement. Real users should sign in without passwords. Sessions must be checked on the server
(Server Components, Server Actions, Route Handlers) and data must be scoped to the session user.

## Decision

- **Better Auth** as a library inside the Next.js app, sessions stored in our Postgres through the
  Drizzle adapter (`src/lib/auth/server.ts`). Auth tables are generated by the Better Auth CLI
  (`pnpm auth:schema`) into `src/lib/db/schema/auth.ts`.
- **GitHub OAuth** for real accounts.
- **Guest accounts** via the `anonymous` plugin. A database hook fills a new guest with demo data;
  `onLinkAccount` moves the guest's cards to the GitHub account if the guest signs in later.
- **Sign-in and sign-out are Server Actions** (`src/features/auth/actions.ts`), so the forms work
  before JavaScript loads and cookies are set by the server.
- **Two layers of checks:** `src/proxy.ts` redirects requests without a session cookie (fast,
  optimistic), and `requireUser()` (`src/lib/auth/session.ts`) verifies the session for every
  protected read and mutation. The UI only ever sees a narrow `CurrentUser` object.
- Post-login redirects accept only same-site paths (`safeRedirectPath`).

## Alternatives considered

- **Auth.js (NextAuth):** the Auth.js project is now maintained by the Better Auth team, and new
  features land in Better Auth. Guest accounts would need custom code.
- **Clerk / hosted auth (incl. Neon Auth):** fastest setup, but hides session handling I want to
  be able to explain, and adds a vendor for a small app.
- **Magic links / passwords:** need email delivery or password storage; GitHub covers the audience.

## Consequences

- One auth stack, one database, no extra vendor.
- Guest users accumulate. A scheduled cleanup of guests older than 7 days is planned (Day 6).
- GitHub OAuth Apps allow one callback URL, so local and production use separate OAuth apps.
- Plugin changes require regenerating the auth schema and a new migration.
